# 1. 알고리즘과 시간복잡도 관계
# 1.1. 개념
> [!summary] 알고리즘과 시간복잡도
> - 알고리즘: 어떤 목적을 달성하거나 결과물을 만들어내기 위해 거쳐야하는 일련의 과정으로 여러가지 상황에 따른 알고리즘은 모두 다르다.
> - 시간복잡도: 알고리즘을 수행하는 **연산의 수**
> - 따라서, 시간복잡도가 가장 낮은 알고리즘을 선택하여 사용한다.
## 1.2. 실행시간
알고리즘의 실행시간을 두 부분으로 나누면 다음과 같다.

1. **입력값의 크기**에 따라 알고리즘의 실행시간을 검증
2. 입력값의 크기에 따른 **함수의 증가량(=성장률)**
이때 중요하지 않는 상수와 계수들을 제거하면 알고리즘의 실행시간에서 가장 중요한 것은 **성장률**이며, 이를 점근적 표기법(Asympotitic notation)이라 부른다.
여기서 점근적은 가장 큰 영향을 주는 항만 계산한다는 의미이다.

## 1.3. 점근적 표기법
점근적 표기법은 크게 3가지로 이를 통해 시간복잡도를 나타내는데 사용된다.

1. 최상의 경우: 오메가 표기법 (Big-$\Omega$ Notation)
2. 평균의 경우: 세타 표기법 (Big-$\Theta$ Notation)
3. 최악의 경우: 빅오 표기법 (Big-O Notation)

평균인 세타 표기법이 가장 정확하고 좋지만 평가하기 까다롭다.
따라서, 최악의 경우인 빅오를 사용한다.
이는 알고리즘이 최악일때의 경우를 판단한면 평균과 가까운 성능으로 예측하기 쉽기 때문이다.

# 2. 빅오 표기법(Big-O)
>[!hint] 불필요한 연산을 제거하여 알고리즘 분석을 쉽게 하는 것이 목적

빅오 표기법으로 측정되는 복잡성은 2가지로 시간복잡도와 공간복잡도가 있다.
- 시간복잡도란 입력된 $N$의 크기에 따라 실행되는 **조작의 수**를 의미한다.
- 공간복잡도는 알고리즘이 실행될 때 사용하는 **메모리의 양**을 나타낸다.
	- 단, 요즘 메모리의 발전으로 중요도는 다소 떨어졌다.

표기법은 `O(n)`과 같이 괄호 안에 표시된다.

# 3. 시간복잡도
시간복잡도란 알고리즘의 성능을 설명하는 지표로 알고리즘을 수행하기 위해 **프로세스가 수행해야하는 연산을 수치화한 값**

> [!question] 실행시간이 아닌 연산수치로 판별하는 이유는?
> 명령어의 실행시간은 하드웨어 및 프로그래밍 언어에 따라 편차가 크게 달라진다.
> 따라서 명령어의 실행 횟수만을 고려한다.

시간복잡도에서 가장 큰 영향을 미치는 단위는 `n`이다.




- 알고리즘 문제에서 실행 시간은 계산량(계산 횟수)와 비례하고, 이 계산량을 order라함
- 이에 계산 횟수가 많은 문제 풀이 방법은 그만큼 실행 시간이 길어지기 때문에 시간 복잡도에서 불리함
- 일반적으로 알고리즘 문제에서 경우의 수가 10의 8승이면, 1초 정도 소요되는 것으로 고려하고, 이를 기준으로 시간 복잡도를 계산함
- 🔍 시간 복잡도 : 10의 8승 = 1억 = 1초
