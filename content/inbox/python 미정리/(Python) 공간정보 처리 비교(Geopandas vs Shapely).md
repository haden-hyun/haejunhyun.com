## 파이썬 공간정보 처리: GeoPandas vs. Shapely 완벽 분석 🗺️

파이썬에서 공간 정보를 다룰 때 **GeoPandas**와 **Shapely**는 가장 핵심적인 라이브러리입니다. 두 라이브러리는 서로 긴밀하게 연결되어 있지만, 목적과 기능에서 뚜렷한 차이를 보입니다.

---

### 1. GeoPandas와 Shapely: 특징과 장단점

#### **🔵 Shapely: 기하 객체 조작의 명수**

Shapely는 개별 **기하 객체(Point, LineString, Polygon 등)를 생성하고 조작**하는 데 특화된 라이브. 공간 데이터의 기하학적 형태 그 자체를 다루는 데 초점을 맞춥니다.

- **주요 특징**
    
    - **객체 지향적:** 파이썬 코드 내에서 점, 선, 면 등의 기하 객체를 직접 생성하고 메서드를 통해 조작할 수 있습니다.
        
    - **다양한 공간 연산:** 두 객체 간의 거리, 교차, 합집합, 차집합 등 다양한 공간 관계 및 분석 기능을 제공합니다.
        
    - **GEOS 래퍼:** C++로 작성된 강력한 기하 엔진인 'GEOS(Geometry Engine - Open Source)'를 파이썬에서 사용할 수 있도록 감싼(wrapping) 라이브러리로, 빠르고 안정적인 연산 성능을 보장합니다.
        
- **장점**
    
    - **직관적인 기하 객체 처리:** 개별 도형을 다루는 작업이 매우 직관적이고 간단합니다.
        
    - **강력한 공간 연산:** 복잡한 기하학적 관계 분석 및 조작에 필수적인 기능들을 제공합니다.
        
    - **가벼움:** 데이터 프레임 구조가 아닌 개별 객체만 다루므로 상대적으로 가볍습니다.
        
- **단점**
    
    - **속성 정보 처리 불가:** '위치'와 '형태' 정보만 다룰 뿐, 해당 공간 객체가 가진 이름, ID, 값 등의 **속성 정보는 함께 처리할 수 없습니다.**
        
    - **데이터 입출력 기능 부재:** Shapefile, GeoJSON 등 공간 데이터 파일을 직접 읽거나 쓸 수 없습니다.
        
    - **시각화 기능 없음:** 자체적인 시각화 기능이 없어 결과를 확인하려면 다른 라이브러리(예: Matplotlib)의 도움이 필요합니다.
        

#### **🟢 GeoPandas: 공간 데이터 프레임의 제왕**

GeoPandas는 우리가 흔히 아는 데이터 분석 라이브러리 **Pandas를 공간 정보에 맞게 확장**한 것입니다. Pandas의 강력한 데이터 처리 능력과 Shapely의 공간 연산 능력을 결합하여 **공간 데이터와 속성 데이터를 함께 다루는 데 최적화**되어 있습니다.

- **주요 특징**
    
    - **GeoDataFrame & GeoSeries:** Pandas의 DataFrame과 Series에 'geometry' 열이 추가된 형태입니다. 'geometry' 열에는 Shapely 객체가 저장되어 각 행의 속성 정보와 기하 정보가 하나로 연결됩니다.
        
    - **다양한 파일 입출력:** Shapefile, GeoJSON, GeoPackage 등 거의 모든 종류의 벡터 기반 공간 데이터 파일을 손쉽게 읽고 쓸 수 있습니다.
        
    - **좌표계 변환(CRS):** 다양한 좌표계를 손쉽게 정의하고 변환할 수 있는 강력한 기능을 내장하고 있습니다.
        
    - **편리한 시각화:** Matplotlib 기반의 간단하고 직관적인 시각화 기능을 제공합니다.
        
- **장점**
    
    - **속성 + 공간 정보 통합 관리:** 데이터의 속성과 위치를 함께 필터링하고 분석하는 데 매우 강력합니다. (예: '서울시에 있는 모든 스타벅스 매장 찾기')
        
    - **Pandas의 강력한 기능 활용:** Pandas의 모든 데이터 조작, 분석, 정렬, 그룹화 기능을 그대로 사용할 수 있습니다.
        
    - **쉬운 데이터 핸들링:** 복잡한 공간 데이터를 파일에서 읽어와 몇 줄의 코드로 시각화까지 완성할 수 있습니다.
        
- **단점**
    
    - **무거움:** Pandas의 데이터 프레임 구조를 기반으로 하므로 개별 객체만 다루는 Shapely보다 상대적으로 무겁고 메모리 사용량이 많습니다.
        
    - **세밀한 기하 조작의 한계:** GeoPandas의 공간 연산은 대부분 GeoSeries(geometry 열) 단위로 이루어집니다. 따라서 매우 복잡하고 세밀한 개별 객체 간의 연산은 Shapely를 직접 사용하는 것이 더 효율적일 수 있습니다.
        

> **결론:** **Shapely**는 '순수한 기하학적 형태'를 다루는 **엔진**의 역할에 가깝고, **GeoPandas**는 이 엔진을 기반으로 속성 데이터를 결합하고 파일 입출력, 시각화 등 **실용적인 데이터 분석 기능**을 덧붙인 **종합 분석 도구**라고 할 수 있습니다. 대부분의 공간 데이터 분석 작업은 GeoPandas로 시작하고, 필요에 따라 GeoDataFrame에서 Shapely 객체를 꺼내와 세밀한 조작을 한 후 다시 GeoDataFrame에 반영하는 방식으로 함께 사용됩니다.

### GeometryCollection의 개념

`GeometryCollection`은 **서로 다른 유형의 기하 객체(예: 점, 선, 면)들을 하나의 컬렉션으로 묶어놓은 객체**입니다. 말 그대로 '기하 객체 모음'으로, 연관성은 있지만 단일 유형으로 표현하기 힘든 다양한 도형들을 한 번에 관리할 때 사용됩니다.

예를 들어, 하나의 `GeometryCollection` 안에는 **`Point`**, **`LineString`**, **`Polygon`** 객체가 모두 포함될 수 있습니다.

Python

```
# Shapely 예시
from shapely.geometry import Point, LineString, Polygon, GeometryCollection

point = Point(0, 0)
line = LineString([(1, 1), (2, 2)])
polygon = Polygon([(3, 3), (4, 3), (4, 4), (3, 4)])

# 점, 선, 면을 하나의 GeometryCollection으로 묶음
collection = GeometryCollection([point, line, polygon])
```

### 기존 Geometry 객체와의 차이점

가장 큰 차이점은 **구성 요소의 동질성 여부**입니다.

- **기존 Geometry 객체 (Point, LineString, Polygon)**
    
    - **단일 유형**으로 구성된 가장 기본적인 기하 형태입니다.
        
    - `Point`는 하나의 점, `LineString`은 연속된 점들로 이루어진 하나의 선, `Polygon`은 닫힌 선으로 구성된 하나의 면을 나타냅니다.
        
    - 이들의 'Multi' 버전 (`MultiPoint`, `MultiLineString`, `MultiPolygon`) 역시 **같은 유형의 객체 여러 개**를 묶은 것이지, 다른 유형이 섞이지 않습니다. 예를 들어, `MultiPolygon`은 여러 개의 `Polygon`으로만 구성됩니다.
        
- **GeometryCollection**
    
    - **서로 다른 유형**의 객체들이 섞여서 하나의 컬렉션을 이룹니다.
        
    - 구성 요소 간의 공간적 연결성이나 규칙이 없을 수 있습니다. 그냥 하나의 그룹으로 묶어놓은 것입니다.
        
    - 이러한 이질적인 구성 때문에 공간 분석 시 다른 단순 객체처럼 동작하지 않을 수 있어 주의가 필요합니다. 예를 들어, `GeometryCollection`의 면적(`area`)이나 길이(`length`)는 그 안에 포함된 `Polygon`들의 총면적과 `LineString`들의 총길이를 합산한 값이 됩니다.
        

|구분|주요 Geometry 객체 (Point, LineString, Polygon, MultiPolygon 등)|GeometryCollection|
|---|---|---|
|**구성**|**동일한 유형**의 기하 객체로만 구성됨|**서로 다른 유형**의 기하 객체들이 혼합될 수 있음|
|**구조**|균일하고 예측 가능한 구조|이질적이고 복합적인 구조|
|**특징**|GIS 분석 및 데이터 모델링에서 표준적으로 사용|여러 종류의 도형을 임시로 묶거나, `split()` 같은 연산의 결과로 반환됨|

### 2. Shapely 핵심 함수 상세 설명

#### **1. `split()`**

`split()` 함수는 하나의 기하 객체(주로 선 또는 면)를 다른 기하 객체(주로 선)를 기준으로 자르는 역할을 합니다.

- **작동 방식:** `split(도형, 자르는_도형)` 형태로 사용하며, 결과는 잘린 여러 개의 도형들이 담긴 `GeometryCollection`으로 반환됩니다.
    
- **예시:**
    
    - **선(LineString)을 점(Point)으로 자르기:** 선 위의 한 점을 기준으로 자르면 두 개의 선으로 나뉩니다.
        
    - **선(LineString)을 선(LineString)으로 자르기:** 긴 선을 가로지르는 짧은 선을 기준으로 자르면 두 개의 선으로 나뉩니다.
        
    - **면(Polygon)을 선(LineString)으로 자르기:** 면을 완전히 가로지르는 선을 기준으로 자르면 두 개의 면으로 나뉩니다.
        
- **그림 예시:**
    
    ```
    (원본 도형)              (자르는 도형)                 (결과: 2개의 Polygon)
    +-----------+
    |           |
    |     A     |  +       |        ->       +-------+   +-------+
    |           |          |                 |       |   |       |
    +-----------+          |                 |   B   |   |   C   |
                           |                 |       |   |       |
                       (LineString)          +-------+   +-------+
      (Polygon A)
    ```
    

#### **2. `unary_union`**

`unary_union`은 여러 개의 기하 객체를 **하나의 단일 객체로 합치는** 함수입니다. 겹치는 부분은 물론, 떨어져 있는 부분까지 모두 포함하여 하나의 `Multi` 객체 또는 단일 객체로 만듭니다.

- **작동 방식:** 주로 GeoPandas의 GeoSeries에 적용하거나, 여러 Shapely 객체의 리스트를 대상으로 사용합니다. 겹치는 경계선을 녹여(dissolve) 하나의 깔끔한 외부 경계선을 가진 도형으로 만듭니다.
    
- **예시:**
    
    - **여러 개의 면(Polygon) 합치기:** 여러 개의 인접한 행정구역(Polygon) 데이터를 합쳐 하나의 광역시(Polygon 또는 MultiPolygon) 경계를 만드는 경우에 사용됩니다.
        
- **그림 예시:**
    
    ```
    (원본 도형들: 3개의 Polygon)           (unary_union 결과: 1개의 Polygon)
    +-------+
    |   A   |---+
    +-------+   |
      |   B   |
      +-------+
      |   C   |
      +-------+
                                  ->      +-----------+
                                          |           |
                                          |     D     |
                                          |           |
                                          +-----------+
    ```
    

#### **3. `linemerge()`**

`linemerge()`는 이름 그대로 **여러 개의 선(LineString)을 하나의 연속된 선으로 합치는** 함수입니다. `unary_union`과 달리, 끝점이 서로 맞닿아 있는 선들만 합쳐줍니다.

- **작동 방식:** `linemerge(선의_리스트_또는_MultiLineString)` 형태로 사용합니다. 선들이 순서에 상관없이 서로의 끝점에서 만난다면, 이를 연결하여 가능한 가장 긴 단일 `LineString`으로 만듭니다. 만약 중간에 끊어지거나 여러 갈래로 나뉘면 `MultiLineString`이 반환됩니다.
    
- **예시:**
    
    - **도로 데이터 정리:** 여러 조각으로 나뉘어 있는 도로 데이터를 하나의 연결된 도로망으로 합칠 때 유용합니다.
        
- **그림 예시:**
    
    ```
    (원본 도형들: 3개의 LineString)            (linemerge 결과: 1개의 LineString)
      A(---)
            B(---)
                  C(---)
    
                                  ->      D(------------------)
    
    ```
    

#### **4. `snap()`**

`snap()` 함수는 한 기하 객체의 꼭짓점(vertex)을 다른 객체의 꼭짓점에 **자석처럼 정확히 붙이는(snapping)** 기능을 합니다. 이는 미세하게 어긋나 있는 데이터를 정합(整合)할 때 매우 유용합니다.

- **작동 방식:** `snap(움직일_도형, 기준_도형, 허용_거리)` 형태로 사용합니다. '움직일 도형'의 꼭짓점 중 '기준 도형'의 꼭짓점과 '허용 거리' 이내에 있는 점들을 '기준 도형'의 해당 꼭짓점으로 정확히 이동시킵니다.
    
- **예시:**
    
    - **경계선 맞추기:** 서로 다른 지도에서 추출하여 미세하게 어긋난 두 필지의 경계선을 정확히 일치시킬 때 사용합니다.
        
- **그림 예시:**
    
    ```
       (원본)                               (snap 적용 후)
    도형 A      도형 B                     도형 A'      도형 B
    +---o       x---------+                +---x---------+
    |   |       |         |                |   '         |
    |   |       |         |       ->       |   '         |
    +---+       +---------+                +---+---------+
     ↑
    (o와 x는 허용 거리 내에 있지만
     정확히 일치하지는 않음)            (A의 꼭지점 o가 B의 꼭지점 x로 이동하여 붙음)
    ```

### 3. GeoPandas에서의 대체 가능성

#### **✅ `unary_union` (대체 가능)**

GeoPandas에는 `unary_union`과 **거의 동일한 기능**을 하는 `dissolve()` 메서드가 있습니다. `dissolve()`는 특정 열(column)의 값을 기준으로 그룹화하여 `unary_union`을 수행하므로 오히려 더 강력하고 실용적입니다.

- **예시:** `gdf.dissolve(by='상위_행정구역')` 코드는 '상위_행정구역' 필드의 값이 같은 모든 도형을 하나로 합쳐줍니다. `by` 인자를 생략하면 전체 GeoDataFrame을 하나의 도형으로 합치므로 `unary_union`과 완전히 동일한 결과를 얻습니다.
    

#### **✅ `split` (부분적 대체 가능, 그러나 복잡함)**

GeoPandas에 `split()`과 직접적으로 일치하는 단일 메서드는 없습니다. 하지만 **`overlay()` 함수를 조합하여 유사한 결과를 낼 수 있습니다.**

- **이유 및 방법:**
    
    1. 잘릴 대상이 되는 면(Polygon) GeoDataFrame과 자르는 기준이 되는 선(LineString) GeoDataFrame을 준비합니다.
        
    2. `overlay(how='difference')`를 사용하여 원본 면에서 선의 영역을 빼냅니다. (선은 면적이 없어 실제로는 변화가 없지만, 연산을 위해 필요)
        
    3. `overlay(how='intersection')` 또는 다른 공간 연산을 통해 잘린 경계를 기준으로 새로운 객체를 생성하는 복잡한 과정을 거쳐야 합니다.
        
- **결론:** 과정이 복잡하고 직관적이지 않아, **면을 선으로 자르는 등의 작업은 GeoDataFrame에서 geometry를 꺼내 Shapely의 `split()`을 직접 적용한 후, 그 결과를 다시 GeoDataFrame으로 만드는 것이 훨씬 효율적**입니다.
    

#### **❌ `linemerge` & `snap` (대체 불가능)**

GeoPandas는 이 두 함수를 직접적으로 대체할 수 있는 고수준의 메서드를 제공하지 않습니다.

- **이유:**
    
    - `linemerge`와 `snap`은 **개별 기하 객체의 위상 관계(topology)와 꼭짓점(vertex) 레벨의 매우 미세한 조작**을 다룹니다.
        
    - 반면 GeoPandas는 **데이터 프레임 단위의 집계, 분석, 필터링**에 초점을 맞추고 있습니다. GeoPandas의 설계 철학은 각 행(row)이 독립적인 하나의 레코드(공간 객체 + 속성)라는 개념에서 출발하기 때문에, 여러 행에 걸쳐 있는 객체들의 연결성을 합치거나(linemerge) 한 객체의 꼭짓점을 다른 객체에 붙이는(snap) 등의 저수준(low-level) 기하 편집 기능은 포함하지 않습니다.
        
    - 이러한 기능들은 GIS 전문 소프트웨어(예: QGIS, ArcGIS)의 편집 도구에 해당하며, 파이썬에서는 이를 구현하는 Shapely를 직접 활용해야 합니다.
        

**결론적으로, GeoPandas는 `dissolve`를 통해 `unary_union`을 효과적으로 대체하지만, `split`, `linemerge`, `snap`과 같이 기하학적 형태 자체를 세밀하게 편집하고 조작하는 기능은 Shapely의 고유 영역으로 남아있습니다.** 따라서 두 라이브러리의 장점을 모두 이해하고 상황에 맞게 함께 사용하는 것이 중요합니다.
