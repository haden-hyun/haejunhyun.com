코드를 작성하다 보면 단순히 위에서 아래로 실행되는 것만으로는 부족할 때가 많습니다. **결측치(NaN)가 있는 데이터는 건너뛰어야 하고, API 호출이 실패하면 재시도해야 하며, DB 연결은 에러가 나도 반드시 끊어줘야 합니다.**

이 글에서는 파이썬 프로그램의 흐름을 정교하게 다루는 **흐름 제어(Loop Control)**와, 서비스의 안정성을 보장하는 **예외 처리(Exception Handling)**를 실무 관점에서 정리합니다.

## 1. 흐름 제어 (Loop Control): 데이터 처리의 핸들링

반복문(`for`, `while`)을 사용할 때, 상황에 맞춰 루프를 제어하는 3가지 핵심 키워드입니다. 데이터 전처리나 로그 분석 시 필수적으로 사용됩니다.

|**키워드**|**대분류**|**의미**|**영향 범위**|
|---|---|---|---|
|**`pass`**|구조 유지|**빈칸 채우기**|흐름에 영향 없음 (아래 코드 실행 O)|
|**`continue`**|회차 제어|**건너뛰기**|현재 회차 중단 (아래 코드 실행 X)|
|**`break`**|루프 제어|**탈출하기**|반복문 전체 종료|

### 1.1 `pass`: "구조 유지를 위한 플레이스홀더"

- **의미:** 문법적 오류를 피하기 위한 빈칸입니다. 기능적으로는 아무것도 수행하지 않습니다.
    
- **실무 활용:** 사용자 정의 예외 클래스를 만들거나, 나중에 구현할 함수(TODO)의 틀을 잡아둘 때 사용합니다.
    

```python

class DataValidationError(Exception):
    """데이터 검증 실패 시 발생하는 에러"""
    pass

def complex_data_pipeline():
    # TODO: 추후 구현 예정
    pass 
```

#### 1. `pass` 키워드: 도대체 왜 쓰는 걸까?

`pass`는 파이썬의 독특한 문법적 특징 때문에 존재하는 키워드입니다.
##### 1.1 사용 이유: "문법적 빈칸 채우기"

C언어나 Java는 중괄호 `{}`로 블록을 구분하기 때문에, 내용이 비어있어도 `{ }`만 쓰면 됩니다. 하지만 **파이썬은 들여쓰기(Indentation)로 블록을 구분**합니다.

따라서 `if`문이나 함수 정의 아래에 아무 코드도 적지 않으면 **문법 에러(IndentationError)**가 발생합니다. 이때 **"아무것도 안 할 거지만, 문법 오류는 내지 마"**라고 알려주는 것이 바로 `pass`입니다.

##### 1.2 실무 활용 패턴

**① 스켈레톤 코드 (Skeleton Code) 작성** 전체적인 구조(Class, Def)를 먼저 잡아놓고, 세부 내용은 나중에 구현할 때 사용합니다.

```python
class DataPipeline:
    def extract(self):
        # TODO: 데이터 추출 로직 구현 예정
        pass

    def transform(self):
        # TODO: 데이터 변환 로직 구현 예정
        pass
```

**② 예외 무시 (Explicitly Ignore)** 에러가 발생해도 아무런 조치 없이 넘어가고 싶을 때 명시적으로 사용합니다.

```python
try:
    os.remove("temp_file.txt")
except FileNotFoundError:
    pass  # 파일이 없으면 그냥 둠 (에러 무시)
```

### 1.2 `continue`: "결측치/오류 데이터 스킵"

- **의미:** 현재 아이템 처리를 중단하고, **다음 반복 회차**로 넘어갑니다.
    
- **실무 활용:** 데이터 전처리 과정에서 `None`, `NaN` 값이거나 형식이 잘못된 로그를 건너뛸 때 주로 사용합니다.
    


```python
# [실무 예시] 로그 파싱 중 유효하지 않은 라인 스킵
raw_logs = ["INFO: User logged in", "", "ERROR: Connection failed"]

for log in raw_logs:
    if not log.strip():  # 빈 줄인 경우
        continue         # 아래 로직 수행 안 하고 다음 로그로 넘어감
    
    # 실제 로그 분석 로직
    print(f"Parsing: {log}")
```

### 1.3 `break`: "조기 종료 (Early Stopping)"

- **의미:** 반복문 자체를 **완전히 종료**하고 탈출합니다.
    
- **실무 활용:** 원하는 데이터를 찾았거나(Search), API 폴링 중 성공 응답을 받았을 때, 머신러닝 학습 시 조기 종료(Early Stopping)에 사용합니다.
    
```python
# [실무 예시] 서버 상태 확인 (Polling) - 성공 시 즉시 종료
max_retries = 5
for i in range(max_retries):
    if check_server_status() == 200:
        print(f"✅ 서버 준비 완료! (시도: {i+1})")
        break  # 더 이상 확인할 필요 없음. 루프 탈출.
    time.sleep(1)
else:
    # break로 끝나지 않고 루프가 끝까지 돌았을 때 실행 (Python 고유 문법)
    print("❌ 서버 연결 시간 초과 (Timeout)")
```

## 2. 예외 처리 (Exception Handling): 시스템 안정성 확보

프로그램 실행 중 발생하는 런타임 에러(Runtime Error)를 제어합니다. 스크립트가 중간에 죽거나 자원(DB, 파일)이 잠기는 것을 방지합니다.

### 2.1 자원 관리의 정석 (`try-except-else-finally`)

단순히 에러를 잡는 것을 넘어, **자원 누수(Resource Leak)**를 방지하는 패턴입니다. `finally`의 역할을 이해하는 것이 핵심입니다.

- **`try`**: 에러 발생 가능성이 있는 비즈니스 로직.
    
- **`except`**: 에러 발생 시 대응 (로깅, 롤백).
    
- **`else`**: 에러 없이 성공했을 때만 실행.
    
- **`finally`**: **무조건 실행**. (DB 연결 종료, 파일 닫기).
    
```python
# [실무 예시] 데이터베이스 트랜잭션 처리 패턴
db_connection = None

try:
    # 1. 시도
    db_connection = connect_to_database()
    data = db_connection.query("SELECT * FROM users")
    
except ConnectionError as e:
    # 2. 실패 시 대응
    print(f"❌ DB 연결 에러: {e}")
    
else:
    # 3. 성공 시에만 실행 (데이터 가공)
    print(f"✅ 데이터 조회 완료: {len(data)}건")

finally:
    # 4. 무조건 실행 (자원 해제)
    # 에러 여부와 관계없이 연결은 반드시 끊어야 함
    if db_connection:
        db_connection.close()
        print("🔒 DB 연결 해제됨")
```

## 3. 능동적 에러 제어: `raise`와 `assert`

에러를 막는 것이 아니라, **잘못된 데이터가 들어왔을 때 확실하게 에러를 터뜨려** 더 큰 문제를 예방하는 기법입니다.

### 3.1 `raise`: "비즈니스 로직 강제"

문법적으로는 맞지만, **로직상 허용하면 안 되는 값**이 들어왔을 때 개발자가 직접 에러를 발생시킵니다.

Python

```
# [실무 예시] 필수 컬럼 검증
def calculate_metrics(df):
    if 'price' not in df.columns:
        # 분석을 진행하면 안 됨 -> 강제로 에러 발생
        raise ValueError("필수 컬럼 누락: 'price' 컬럼이 없습니다.")
            
    return df['price'].mean()
```

### 3.2 `assert`: "단언 및 디버깅"

"이 시점에는 데이터가 무조건 이 상태여야 해"라고 선언합니다. 주로 데이터의 형태(Shape)나 분포가 예상과 맞는지 **검증(Validation)**할 때 사용합니다.

Python

```
# [실무 예시] 데이터 분할 검증
# Train set과 Test set의 합은 전체 데이터 수와 같아야 함
assert len(train) + len(test) == total_count, "데이터 누실 발생!"
```

## 4. Deep Dive: 왜 `if` 대신 `assert`를 쓸까?

기능적으로 보면 `assert`는 `if`문으로 대체 가능합니다. 하지만 현업에서 굳이 `assert`를 사용하는 데에는 **3가지 명확한 이유**가 있습니다.

### ① 성능 최적화 ("사라지는 코드")

- **`if` 문:** 실제 운영(Production) 환경에서도 매번 실행되어 CPU를 소모합니다.
    
- **`assert` 문:** 파이썬 실행 시 최적화 옵션(`-O`)을 주면 **컴파일 과정에서 삭제**됩니다.
    
    - 즉, 개발/테스트 단계에서는 꼼꼼하게 검사하고, **실제 배포 시에는 성능 저하 없이(0ms) 실행**할 수 있습니다.
        

### ② 의도의 명확성 (Signal)

- **`if` 사용:** "사용자가 입력을 잘못했거나, 파일이 없는 등 **런타임에 일어날 수 있는 예외 상황**"을 처리한다는 뉘앙스입니다.
    
- **`assert` 사용:** "여기서 에러가 난다면, 그건 **개발자가 로직을 잘못 짠 것(버그)**이다"라는 강력한 신호입니다. 이를 **불변 조건(Invariant)** 확인이라고 합니다.
    

### ③ 가독성과 디버깅

방어 코드를 한 줄로 간결하게 작성하여 핵심 로직의 흐름을 방해하지 않습니다.

|**구분**|**if + raise**|**assert**|
|---|---|---|
|**대상**|사용자 입력, 외부 환경 (파일/네트워크)|**개발자 로직 검증 (내부 버그)**|
|**배포 시**|**실행됨** (필수 로직)|**삭제 가능** (`-O` 옵션 사용 시)|
|**의미**|"에러가 나면 처리해줘"|"이게 틀리면 내 코드는 버그야"|

> **⚠️ 주의:** `assert`는 배포 시 삭제될 수 있으므로, 비밀번호 확인이나 권한 체크 같은 **보안 로직에는 절대로 사용하면 안 됩니다.**
