# Featured — 큐레이션 목록으로 통일

- 날짜: 2026-08-08
- 대상: `plugins/featured-notes`, `quartz.config.yaml`
- 상태: 구현 완료

## 배경

Featured 지정 수단이 `frontmatter.featured: true` 하나였고, 실제로 쓰는 노트는 0개였다.
게다가 그 값을 달아도 **어느 것이 대형 카드가 될지 고를 수 없었다** — 선정분을 다시
최신순으로 정렬했기 때문이다.

## 결정

지정 수단을 `quartz.config.yaml`의 `options.slugs` 배열 하나로 통일한다.
`frontmatter.featured`는 삭제한다. 지정하는 곳이 두 군데면 "어디서 정해졌는지"를
매번 추적해야 한다 — 색·폰트에서 이미 겪은 분열과 같은 모양이다.

vault 안 큐레이션 노트(위키링크 목록) 안은 기각했다. `file.links`로 읽는 것 자체는
가능하지만, 그 노트가 `allFiles`에 남아야 해서 Recent Notes·Archive·CATALOG에 노출되고
홈 통계 노트 수가 1 늘어난다. 우리 플러그인 20종 중 `unlisted`를 보는 건
`related-notes` 하나뿐이라 제외 처리를 여러 곳에 심어야 한다.

발행이 항상 로컬 저장소에서의 `npx quartz build`를 거치므로(`content/`가 심볼릭 링크라
원격 빌드 불가), 설정 파일을 고치는 것이 추가 부담이 아니라는 점이 결정적이었다.

## 동작

슬롯은 4개 — 대형 1 + 소형 3.

1. `slugs`를 **쓴 순서 그대로** 해석한다. 첫 항목이 대형 카드.
2. 부족분은 기존 토픽 라운드로빈으로 채우고, **자동 채움분만** 최신순 정렬한다.
   목록 순서를 뒤에서 다시 정렬하지 않는 것이 이 방식의 존재 이유다.
3. `slugs`가 비면 전부 자동 — 도입 전과 결과가 같다.

### 경고

오타가 조용히 무시되면 "설정했는데 안 나온다"가 된다. 빌드 로그에 남긴다.

- 해석 실패: `슬러그를 찾을 수 없어 건너뜁니다: "..."`
- 중복: `중복된 슬러그를 건너뜁니다: "..."`
- 초과: `슬롯은 4개인데 N개가 지정됐습니다. 뒤 M개는 표시되지 않습니다.`

### 중복 노출 방지

`recentExcludeCount`(Recent Notes 상위 N개 제외)는 **자동 채움에만** 적용한다.
목록 지정분은 제외하지 않는다 — 작성자 의도가 우선이다.
N은 `recent-notes-index.limit`과 같은 값으로 유지할 것.

## 검증 결과

- `slugs: []`로 빌드한 Featured 섹션이 도입 전 출력과 **바이트 단위로 동일**
- 목록 지정 시 대형 카드 = 첫 항목, 사이드 = 2~4번째 (순서 그대로)
- 경고 3종 모두 빌드 로그에 출력됨
- 유효·중복제거 후 앞 4개만 렌더됨

## 범위 밖 — 별도 과제

빌드마다 자동 선정 결과가 달라지는 현상을 확인했다. 원인은 이 설계가 아니라
**vault frontmatter의 날짜 키**다. `created-modified-date`는
`frontmatter.created / modified / published`만 읽는데, 노트 91개 중 90개가
`updated:`를 쓴다. 그래서 `modified`가 frontmatter에서 해석되지 않고 git → 파일
mtime으로 떨어지고, Obsidian이 파일을 건드릴 때마다 순서가 흔들린다.

Featured는 목록으로 고정되지만, Recent Notes 정렬·표시 날짜와 GlobalNav의
"최신 노트" 링크는 여전히 이 문제의 영향을 받는다.
