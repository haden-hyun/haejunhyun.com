## 1. 배경: 왜 바꾸나

kciter.so 홈의 회전하는 ASCII 커피잔을 참고해 색소폰을 만들었는데 "너무 똑같다"는 문제가 있었다. 2026-10-23에 kciter.so 번들(`/_astro/HomeHero.astro_astro_type_script_index_0_lang.BnHJ_LSM.js`)을 직접 받아 비교했더니 구조뿐 아니라 파라미터까지 겹쳤다.

| 항목 | kciter.so 커피잔 | 현재 `sax.ts` |
|---|---|---|
| 본체 문자 램프 | `·.-:~;+=*o%#@` | 같음 |
| 김/입자 | 3줄기 × 14개, ` ·.:~` | 같음 |
| 회전 | Y축 0.32 rad/s | 0.3 rad/s |
| 드래그 | 0.012 rad/px + 관성 | 같음 |
| 기타 | ink/fx 두 겹 `<pre>`, IO·reduced-motion 정지, 첫 프레임 프리렌더 | 같음 |

결론: 오브젝트만 머그→색소폰으로 바뀌었다. 차별화하려면 **문자 램프와 "위로 오르는 김" 문법**을 바꿔야 한다.

## 3. 확정 결정 사항

사용자 결정(2026-10-23): 본체는 이름+기호 조합, 가지는 음표 특수문자, 가지 끝에는 토픽, **기존처럼 회전**.

### 3.1 본체 램프 — 이름 + 기호

밝기 13단계(0~12)를 세 구간으로 나눈다.

| 구간 | 문자 | 의도 |
|---|---|---|
| 0~4 (어두운 면) | `·.-:~` | 형태의 그림자 |
| 5~10 (중간 톤) | `haejunhyun` 글자 | 이름. 칸 위치에 고정 `NAME[(c + r*3) % 10]`이라 가로로 이어 읽힌다 |
| 11~12 (하이라이트) | `#@` | 금속 반사 |

이름 글자를 셀 위치에 고정했기 때문에, 색소폰이 돌면 이름이 몸통 위를 흐르는 것처럼 보인다. kciter 램프와 겹치는 글자는 `·.-:~#@` 일부뿐이고, 질감이 확실히 다르다.

### 3.2 가지·잎·라벨

| 요소 | 규칙 |
|---|---|
| 가지 | 토픽 7개. `♪` 기본, 4칸마다 `♫`. 벨 둘레(반지름 0.26)에서 바깥 0.75 : 위 1 방향으로 3D 무작위 걸음(step 0.03). 길이 `0.42 + √노트수 × 0.13` |
| 곁가지 | 7점마다 확률 0.6, 남은 길이 × 0.4 |
| 잎 | 노트 1개 = 잎 1개. 가지를 따라 날짜순(끝이 최신), 좌우 교대로 0.065 떨어짐. `,` 2년 넘음 · `*` 보통 · `@` 최근 45일 |
| 라벨 | 가지가 다 자란 뒤 끝에 토픽명(`programming`, `data-eng`, `data-sci`, `cs`, `gis`, `finance`, `tools`). 오른쪽에 공간이 없으면 왼쪽 |
| 시드 | 토픽별 고정 시드(`mulberry32(31 + i*13)`) — 방문할 때마다 같은 모양 |

### 3.3 움직임

| 항목 | 값 |
|---|---|
| 회전·드래그·관성 | 현재 `HomeHero.tsx`와 같은 상수(자동 0.3 rad/s, 0.012 rad/px, 기본 자세 ay -0.35 / ax -0.25) |
| 가지 | 3D 점이라 본체와 함께 돈다. 셀별 최전면 깊이로 가림 판정 — 몸통 뒤로 가면 숨는다 |
| 성장 | 토픽마다 0.12초 시차, 2.6초 동안 자라고 정지. 최근 45일 잎은 성장 후 `.`→`o`→`@`로 핀다 |
| 김 입자 | **삭제**(kciter 문법) |
| reduced-motion | 회전 없음, 다 자란 상태 |
| 그리드 | 100×45 칸, 투영 중심 (42, 24), 글자 6px / 줄 6.5px. 색소폰 크기(투영 배율 74)는 현재와 같다 |

### 3.4 색(레이어)

`<pre>` 4겹 유지. 테마 변수만 쓴다.

| 레이어 | 대상 | 색 |
|---|---|---|
| l1 | 토픽 라벨 | `--gray` 쪽 muted |
| l2 | 가지 `♪♫` | `--secondary` 55% |
| l3 | 본체, 잎 | `--secondary` |
| l4 | 최근 잎·hover 잎 | `--dark` 굵게 |

## 4. 구현 계획 (블로그 저장소 `plugins/home-hero`)

1. **`sax.ts`**
   - `renderSax`를 래스터 단계(셀별 밝기·최전면 깊이)와 문자 선택 단계로 나눈다(프로토타입의 `rasterSax` 참고).
   - `bodyChar(v, r, c)`를 추가하고, 김 입자 코드를 지운다.
   - `buildVine(notes)` / `drawVine(...)`을 추가한다. 둘 다 `toString()`으로 인라인되므로 **바깥 식별자·import를 참조하지 말 것**(파일 상단 주의 그대로).
2. **`HomeHero.tsx`**
   - 빌드 시 `allFiles`에서 노트 목록을 뽑는다. `isListedNote` + 슬러그 첫 세그먼트 = 토픽, 프론트매터 날짜, 제목.
   - 토픽·날짜만 담은 압축 JSON을 인라인 스크립트에 넣는다(제목은 hover 캡션용으로만).
   - 토픽 표시명은 `_shared`의 토픽 표시명 유틸을 재사용한다.
   - 첫 프레임 프리렌더는 **다 자란 상태**로 굽는다(no-JS·reduced-motion에서 완성된 정원이 보이게).
3. **최근 판정 기준일**: 빌드 날짜 기준 45일. 빌드가 뜸하면 오래 "최근"으로 남는다는 점을 감안한다(대안: 클라이언트에서 `Date.now()`로 다시 판정).
4. **`hero.scss`**: `.hero-sax` 크기를 100×45 칸에 맞추고, 음표 상자 `.n { display:inline-block; width:1ch }`를 추가한다.
5. 빌드: `plugins/home-hero`에서 `npm run build`(tsup) → `dist/` 커밋. 프로덕션 `public/` 빌드는 Mac에서(Windows 클론은 `content` 링크 문제로 빌드 불가 — anim 인계서 9항과 같은 사정).
6. 블로그 저장소 규칙상 인계 문서는 거기 만들지 않는다. 확정되면 결정은 `DESIGN-SYSTEM.md`에 현재 상태로만 적는다.

## 5. 주의·미검증

- **`♪♫` 글리프**: 블로그 코드 폰트에 없으면 대체 폰트로 그려져 폭이 달라진다. 프로토타입은 음표를 `1ch` 상자로 감싸 정렬을 지킨다. 실사이트 코드 폰트에서 실측해야 한다.
- **노트가 늘면** `programming` 가지가 계속 길어진다. 길이는 √로 눌렀지만, 노트 200개 이상이면 상한(예: 1.4)이 필요하다.
- **라벨 겹침**: 회전 중 라벨끼리 잠깐 겹칠 수 있다. 정지 자세에서는 겹치지 않음을 텍스트 렌더로 확인했다.
- **성능**: 프레임마다 `innerHTML`로 4겹을 갱신한다(30fps). 현재 `textContent` 방식보다 무겁다. 음표를 쓰지 않는 레이어는 `textContent`로 두는 최적화를 검토한다.
- 브라우저에서 실제 렌더는 사용자가 확인해야 한다. Node 텍스트 렌더로는 자세 2개에서 형태와 가림 판정을 확인했다.
