결정적 변수는 색상 수가 아니라 명도 스프레드였습니다. 널리 쓰이는 라이트 테마의 실측값 — GitHub Light 10.11 · One Light 8.39. 이전 안은 유채색 4종이 6.0~7.4에 몰려(스프레드 1.31) 전부 "같은 명도의 어두운 덩어리"였고, 색상만으로 구별해야 해서 스캔이 느렸습니다. 지금은 9.47입니다 — 명도가 1차 신호, 색상이 2차 신호입니다.

역할별 배치: 주석은 가장 옅게(건너뛸 수 있게), 키워드도 옅게(if/for는 형태로 이미 식별됨), 문자열은 매우 진하게(데이터 덩어리로 한눈에), 식별자가 가장 진하게(실제로 읽는 내용).

컨셉은 판독성을 해치지 않는 선에서 결합했습니다 — string·value는 accent(H207) 계열, keyword는 Blue Note 브릭(#b8442a). 결과적으로 코드블럭이 잉크 + 블루 + 브릭이라는 Blue Note 원전의 3색 구성이 됩니다.

인라인 코드 · 수식

Airflow에서 Connection은 접속 정보를 담는 그릇이고 Hook은 그것을 클라이언트로 바꾸는 어댑터입니다. conn_id로 조회합니다.

P(A│B) = 사후확률 = P(B│A)·P(A) / P(B)

인라인 코드는 색이 아니라 재질로 구분합니다 — 모노스페이스 + 배경 + 보더로 이미 세 겹이라 색은 네 번째 중복 채널입니다.

수식 안 한글은 KaTeX 폰트에 글리프가 없어 브라우저 기본(굴림)으로 떨어졌습니다. KaTeX가 붙여주는 hangul_fallback 클래스를 본문 서체로 넘겨 해결했습니다.

Airflow Connection과 Hook의 관계

2026-08-01 · 7 min read
airflowdata-engineering
📌 Summary

Connection은 접속 정보를 저장하는 설정이고, Hook은 그 설정을 읽어 실제 클라이언트를 만들어주는 코드다. 이 경계를 지키면 DAG에 자격 증명이 하드코딩되지 않는다.

Airflow를 처음 쓸 때 가장 헷갈리는 지점이 Connection과 Hook의 역할 구분입니다. 이름만 보면 둘 다 "연결"처럼 보이지만, 실제로는 층이 다릅니다.

Connection — 접속 정보를 담는 그릇

Connection은 Airflow 메타데이터 DB에 저장되는 레코드입니다. 호스트, 포트, 로그인, 비밀번호, 그리고 extra JSON 필드를 갖습니다.

# 환경변수로 등록하면 DB 없이도 동작한다
export AIRFLOW_CONN_MY_PG='postgresql://user:pw@localhost:5432/db'

여기서 중요한 건 Connection 자체는 아무것도 연결하지 않는다는 점입니다. 그저 값의 묶음일 뿐이고, 실제 접속은 Hook이 담당합니다.

⚠️ 주의

extra 필드에 넣은 값은 UI에서 마스킹되지 않습니다. 민감 정보는 반드시 password 필드를 쓰세요.

Hook — 설정을 클라이언트로 바꾸는 어댑터

Hook은 conn_id를 받아 해당 Connection을 조회하고, 그 값으로 실제 클라이언트 객체를 만들어 돌려줍니다. PostgresHook은 psycopg2 커넥션을, S3Hook은 boto3 클라이언트를 반환하는 식입니다.

from airflow.providers.postgres.hooks.postgres import PostgresHook

def extract():
    hook = PostgresHook(conn_id="my_pg")
    # 자격 증명은 코드 어디에도 없다
    return hook.get_records("SELECT * FROM users")

DAG 파일에 비밀번호를 적는 순간, 그 저장소는 더 이상 공개할 수 없게 된다.

💡 Tip

같은 Hook을 여러 환경에서 쓰려면 conn_id만 환경변수로 바꾸면 됩니다. 코드는 그대로입니다.

📖 참고

Airflow 공식 문서의 Managing Connections · Hooks 항목.

정리하면, Connection은 배포 환경마다 달라지는 값이고 Hook은 환경과 무관한 코드입니다. 이 경계를 지키면 같은 DAG를 로컬·스테이징·운영에서 그대로 돌릴 수 있습니다.
