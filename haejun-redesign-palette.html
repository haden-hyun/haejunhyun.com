Airflow Connection과 Hook의 관계

2026-08-01 · 7 min read
airflowdata-engineering
📌 Summary

Connection은 접속 정보를 저장하는 설정이고, Hook은 그 설정을 읽어 실제 클라이언트를 만들어주는 코드다. 이 경계를 지키면 DAG에 자격 증명이 하드코딩되지 않는다.

Airflow를 처음 쓸 때 가장 헷갈리는 지점이 Connection과 Hook의 역할 구분입니다. 이름만 보면 둘 다 "연결"처럼 보이지만, 실제로는 층이 다릅니다.

Connection — 접속 정보를 담는 그릇

Connection은 Airflow 메타데이터 DB에 저장되는 레코드입니다. 호스트, 포트, 로그인, 비밀번호, 그리고 extra JSON 필드를 갖습니다. UI나 CLI, 환경변수로 등록할 수 있습니다.

# 환경변수로 등록하면 DB 없이도 동작한다
export AIRFLOW_CONN_MY_PG='postgresql://user:pw@localhost:5432/db'

여기서 중요한 건 Connection 자체는 아무것도 연결하지 않는다는 점입니다. 그저 값의 묶음일 뿐이고, 실제 접속은 Hook이 담당합니다.

Hook — 설정을 클라이언트로 바꾸는 어댑터

Hook은 conn_id를 받아 해당 Connection을 조회하고, 그 값으로 실제 클라이언트 객체를 만들어 돌려줍니다. PostgresHook은 psycopg2 커넥션을, S3Hook은 boto3 클라이언트를 반환하는 식입니다.

from airflow.providers.postgres.hooks.postgres import PostgresHook

def extract():
    hook = PostgresHook(conn_id="my_pg")
    # 자격 증명은 코드 어디에도 없다
    return hook.get_records("SELECT * FROM users")

DAG 파일에 비밀번호를 적는 순간, 그 저장소는 더 이상 공개할 수 없게 된다.

언제 무엇을 쓰나

상황ConnectionHook
접속 정보 변경UI에서 수정코드 변경 없음
새 DB 추가conn_id 신규 등록같은 Hook 재사용
커스텀 로직 필요변경 없음Hook 상속

정리하면, Connection은 배포 환경마다 달라지는 값이고 Hook은 환경과 무관한 코드입니다. 이 경계를 지키면 같은 DAG를 로컬·스테이징·운영에서 그대로 돌릴 수 있습니다.
